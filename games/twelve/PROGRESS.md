남은 것: **8~12지형(6단계 나머지)** · 최종보스(7단계) · 어려움 모드(8단계 나머지) · 그림/소리(9단계) · 밸런스·실제 폰 확인(10단계). 지도에는 8~12지형과 최종보스가 아직 '준비 중'으로 보인다.
브랜치 `feature/twelve-2` (푸시하지 않음 — 메인 세션이 한다). **`078_twelve.sql` 은 운영에 있으니 고치지 않는다.** 새 SQL 은 `089_twelve_full.sql` 하나에(아직 푸시 전이라 이어서 고쳐도 된다, 080 이상 금지).

## 해 보기

```bash
cd games/twelve
npm run dev      # http://localhost:5297/games/twelve/?local=1
npm test         # 397개
npm run build
npm run gen      # src/data/maps/r01~r07.ts 다시 만들기 (맵 생성).  -- 5 6 = 그 지형만
npm run sqlgen   # src/data 의 숫자로 supabase/migrations/089_twelve_full.sql 의 표(gen 블록)를 다시 쓴다 (078 은 건드리지 않는다)
npm run pace     # 플레이 시간·레벨 곡선 표 (1~7지형, 2분쯤).  -- 4 = 4지형까지,  -- 7 1 = 지형 수·씨앗 수,  -- weapons = 무기 4종 비교
npm run tower    # 끝없는 탑을 자동 조종이 몇 층까지 오르는지 (레벨별, 30초쯤).  -- 5 = 씨앗 수
```

개발 옵션 (`?local=1` 뒤에): `&map=1-3`(바로 그 맵) · `&lv=50` · `&god=1`(무적) · `&all=1`(모두 열림) · `&hero=tiger` · `&weapon=bow`(가방의 그 종류 무기를 든다).
개발 옵션으로 하는 판은 저장하지 않는다. 테스트 모드에서는 콘솔의 `__twelve` 가 지금 판 상태(RunState)다.
테스트 모드의 기록은 `localStorage['sia-twelve-local-v2']` (지우면 처음부터. 엽전·장비를 넣어 보려면 이 값을 고친다).
PC 키: WASD/방향키 이동, J 공격, K·L 스킬, U 고유 스킬, 스페이스 구르기, 1·2 물약, Esc 일시정지.

## 만든 것

- **6단계 — 4~7지형 (2차 작업 1부, 2026-11-23):** 토끼의 달동산 · 용의 연못 · 뱀의 늪 · 말의 성문. 지형마다 맵 8개(지형 조각 4개씩: `MOON` · `POND` · `SWAMP` · `GATE`), 새 행동의 요괴 하나(그슨대 = 숨기 · 메기 요괴 = 끌어당기기 · 독두꺼비 = 독 웅덩이 · 화약 도깨비 = 자폭), 보스 고유 공격(장산범 = 뛰어들기 · 왕지네 = 나란한 줄 훑기 · 구미호 = 여우구슬·독불 · 수문장 대장 = 화살 비), 환경 효과와 막는 대원(달그림자 = 쥐 · 물길 = 뱀 · 독안개 = 말 · 성벽 화살 = 원숭이), 보스 대사 3줄·한마디, 합류 한마디(말 · 양 · 원숭이 · 닭). 세부 규칙·숫자는 PRD '구현 메모 — 6단계 — 4~7지형'.
  - **서버:** `089_twelve_full.sql` (078 의 표 함수 15개를 다시 정의 — 맵 56줄). `scripts/sqlgen.ts` 는 089 를 쓰고, `tests/sql.test.ts` 는 078 + 089 를 합쳐 마지막 정의를 대조한다. PGlite 로 001~087 + 089 를 적용해 **291단계(2~7지형을 차례로 깨는 48판 포함)가 기기 규칙과 같다**는 것을 확인했다.
  - **밸런스:** 경험치 곡선 130n^1.4 · 5지형부터 요괴 체력 오름(`HP_RAMP`) · 강철부터 강화 값 · pace 가정(5지형부터 사냥 두 바퀴). 1~4지형 3.75시간 Lv24.5, 1~7지형 7.41시간 Lv39.8 (아래 'pace 결과').

- **10단계 일부 (아이폰 WebKit 확인, 2026-11-23):** Playwright WebKit 의 iPhone 15 설정(393×852 = 홈 화면 앱 크기)과 iPhone SE 크기(375×667)로 `?local=1` 을 열어 화면 전부와 터치 조작을 봤다. 고친 것:
  - **전투 화면이 긴 화면을 꽉 채운다.** 그림판이 720×1280 고정이라 아이폰에서는 위아래에 76px 띠가 남았다 → 높이를 화면 비율에 맞춘다(`viewHeight`: 1280~1600, 아이폰 15 는 720×1561). `GameScene` 은 `H` 대신 `this.vh` 를 쓴다.
  - **카메라가 맵 위·아래 끝을 조금 넘어간다**(`CAM_OVER_TOP` 0.1 · `CAM_OVER_BOTTOM` 0.3, 맵 밖은 벽 색). 맵 끝에 딱 맞추면 시작 자리의 대원이 조이스틱·버튼 밑에 깔렸다. 탑의 방(22줄)처럼 화면보다 짧은 방도 같은 식으로 대원을 따라간다.
  - **그림판 크기 다시 맞추기:** 전투 화면 자리(`#game`)를 `ResizeObserver` 로 보고 `game.scale.refresh()` 를 부른다 (Phaser 는 화면이 자리 잡기 전에 만들어지면 작게 굳은 채로 남았다 — `&map=` 로 바로 들어갈 때 나왔다).
  - **누르는 것 44px 이상:** `.btn.small`(쉼터 줄 · 상점 사기 · 사기/팔기 탭 · 탑 층 고르기 · 설정 켬/끔 · 건너뛰기) 35~40px → 44px, 뒤로 34px → 44px, 일시정지 40px → 44px.
  - **윗줄 깨짐:** 알약이 둘(레벨·엽전 / 강화석·엽전)인 화면에서 '← 뒤로'가 세로로 꺾였다(탑 · 대장간) → 뒤로는 줄바꿈 없음, 알약 둘이면 알약과 제목을 작게, 제목은 넘치면 말줄임. 탑 제목에서 그림 글자를 뺐다.
  - 하늘 배경 아래쪽(크림색)의 흰 안내 글(`.light`)이 안 읽혀서 외곽선을 둘렀다. 탑 보스 층에서 '여기서 그만하기'를 누르면 카드 두 장이 겹쳐 보이던 것을 고쳤다. `#game` 에 `touch-action: none`.
  - 테스트 모드에서 `window.__twelveGame`(Phaser.Game)을 내놓는다 — 그림 메모리를 잴 때 쓴다.

- **8단계 일부 (끝없는 탑):** 메인의 '🗼 끝없는 탑' → 내 기록 · 시작할 층 고르기(1층 + 깬 보스 층의 다음 층) → 층마다 방 하나(16×22칸), 5층마다 정예, 10층마다 보스. 층을 깨면 그 자리에서 엽전·강화석·장비를 받고(카드가 잠깐 뜨고 다음 층으로, 보스 층은 계속/그만 고르기), 쓰러지면 판이 끝난다. 체력·마력·물약은 층을 넘어 이어진다. 서버 RPC 3개(`twelve_tower_start` · `_floor` · `_end`) + `?local=1` 같은 규칙. 세부 규칙·숫자는 PRD '구현 메모 — 8단계 일부'.

- **078 은 운영에 있다. 고치지 않는다.** 2차 작업에서 바꾸는 함수·표는 089 에 `create or replace` 로 다시 정의한다(뒤 정의가 이긴다). 새 RPC(예: `twelve_set_mode`)나 최종보스 맵을 다루게 고친 `twelve_start` · `twelve_finish` 도 089 에 넣는다 — `tests/sql.test.ts` 의 `fn()` 은 두 파일을 합친 것에서 마지막 정의를 본다. 새 표·열이 필요하면 `create table if not exists` · `alter table … add column if not exists` 를 089 에 넣고, sql.test 의 '089 는 … create table 이 없다' 검사를 그에 맞게 고친다.

- **RPC:** `twelve_state()` · `twelve_start(map, mode, hero)` → `{run, seed}` · `twelve_finish(run, report)` → `{state, result}` · `twelve_set_hero` · `twelve_equip` · `twelve_unequip` · `twelve_lock` · `twelve_claim` · `twelve_sell` · `twelve_scrap` · `twelve_enhance` · `twelve_buy(what, n)`. 모두 `{…state}`(= `TwelveProfile` 모양)를 돌려준다.
- **끝없는 탑 RPC:** `twelve_tower_start(floor, hero)` → `{run, seed, base}` · `twelve_tower_floor(run, floor, time, potions)` → `{state, result: {floor, coins, stones, items, siaCoin, time, best}}` · `twelve_tower_end(run, potions)` → `{…state}`. 기록은 `twelve_tower`(최고 층 · 시간 · 레벨 · 대원 · 날짜 · 체크포인트 `cps`), 진행 중인 판은 `twelve_tower_runs`. 상태(`state.tower`)에 내 탑 기록이 들어 있다(없으면 null).
- **랭킹 뷰:** `twelve_level_ranking`(한 맵이라도 깬 사람) · `twelve_tower_ranking`(탑에 한 번이라도 들어간 사람). 누구나 읽는다 — 랭킹 창이 다른 게임처럼 뷰를 바로 읽는다.
- **화면이 보내는 것:** 종류별 잡은 수 · 정예 수 · 보스 · 시간 · 상자 · 쓰러진 횟수 · 쓴 물약. 경험치·엽전·드랍·확정 보정·열쇠·별·시아코인은 서버가 계산한다.
- **표는 손으로 고치지 않는다:** 089 의 `-- <gen:이름>` 블록은 `npm run sqlgen` 이 만든다 (078 의 블록은 옛 값 그대로 남는다 — 보지 않는다). `tests/sql.test.ts` 가 블록마다 대조하므로, `src/data` 숫자를 바꾸고 sqlgen 을 안 돌리면 테스트가 깨진다.
- **규칙이 두 곳에 있다:** `progress.ts`(checkReport · applyReport) · `drops.ts` · `rules.ts` · `tower.ts` ↔ `twelve_finish` 와 상점·대장간 · 탑 RPC. 한쪽을 바꾸면 다른 쪽도 바꾸고 아래 확인 도구를 돌릴 것.
- **맵 표에 줄이 있는 맵만 시작할 수 있다** (`_twelve_maps` — 지금 56줄). 지형을 더 열면 sqlgen 이 줄을 더한다. 상점 등급·탑의 레어 목록도 이 표에 맵이 있는 지형까지만 본다(`_twelve_shop_tier`).

## 알려진 문제 · 아직 안 한 것

- **밸런스는 자동 조종 기준이다.** 사람 시간은 '자동 조종 × 1.3 + 판마다 30초'로 어림했다. 실제로 해 보고 `scripts/pace.ts` 의 `HUMAN` 과 맵 길이를 다시 맞춰야 한다. 자동 조종이 쓰러지지 않아 '쓰러져서 다시 하는 시간'과 난이도는 표에 안 보인다.
- **지형의 첫 맵이 쉽다.** 앞 지형 보스를 잡고 오면 레벨이 권장보다 높아 2-1 · 3-1 · 5-1 · 7-1 은 2~4분에 끝난다. 그 맵의 별 시간도 넉넉하다(자동 조종의 2배).
- **엽전이 남는다 (5지형부터 더).** 7지형 끝에 약 6만. 무기·방어구가 착용 레벨에 묶여 있어(강철 Lv27 · 백은 Lv36) 6지형처럼 새 등급이 없는 지형에서는 쓸 곳이 물약뿐이다. 강화 값을 강철부터 올렸지만 모자라다 — 장신구 사기·강화석 사기 같은 쓸 곳을 더하거나 요괴 엽전을 줄이는 것은 10단계(밸런스)에서.
- **4~7지형은 자동 조종과 머리 없는 WebKit 으로만 봤다.** 사람이 해 보지 않았다: 그슨대가 얼마나 보이는지(지금 불투명도 16~22%) · 달그림자 반지름(330px = 화면 너비의 절반쯤) · 물살 세기 · 독 피해 · 화살 간격은 해 보고 맞춰야 한다(`ENV`).
- **달그림자는 요괴만 가린다.** 날아오는 불·예고 범위·떨어진 것·작은 지도는 그대로 보인다. 작은 지도에 요괴 점이 있다면 그것도 그대로다.
- **물살·독은 대원에게만 걸린다** (요괴는 물에서 밀리지 않고 늪에서 다치지 않는다). 진흙·골바람과 같다.
- **끝없는 탑이 조금 어려워졌다.** `HP_RAMP` 와 4~7지형 보스의 새 공격 때문에 자동 조종 기준 Lv18 약 35 → 31층, Lv36 약 62 → 54층.
- **화약 도깨비가 터져도 처치로 센다.** 가만히 맞아 주기만 해도 경험치·엽전을 받는다(체력이 낮고 수가 적어 큰 차이는 아니다). 서버 최대치·출구 조건과 어긋나지 않게 하려는 선택이다.
- **5~7지형의 5·6·7번 맵은 요괴가 150~172마리**다(1~3지형은 최대 172). 성능은 다시 재지 않았다 — 독 웅덩이·여우구슬(구슬 12개)이 더해졌다.
- **새 요괴 여섯은 기존 그림에 색만 입혔다** (진흙 요괴 = 물귀신 그림, 살쾡이 요괴 = 여우불, 그슨대 = 원혼, 메기 요괴 = 방망이 도깨비, 독두꺼비 · 화약 도깨비 = 꼬마 도깨비). 시작 장면도 기존 그림을 모은 것이다. 필요한 그림은 `ASSETS.md`.
- **골바람은 요괴를 밀지 않는다** (대원만). 진흙도 대원만 느려진다.
- **한꺼번에 팔기·분해**는 일반 무기·방어구만 한다 (착용 · 잠금 · 레어 · 장신구 · 강화한 것 · 종류마다 가장 좋은 무기 하나는 남긴다). 장신구는 하나씩 정리해야 한다.
- **정예를 보스보다 나중에 잡으면** 확정 보정 경계에서 전투 화면의 빛기둥과 결과가 다를 수 있다 (서버는 정예 → 보스 순서로 판정).
- **서버 RPC 를 진짜 Supabase 에서 불러 보지 않았다.** PGlite 확인과 `createSupabaseApi` 단위 테스트(가짜 RPC)만 했다. 게임은 닫혀 있으니, 배포 뒤 관리자 계정으로 맵 한 판 · 탑 몇 층 · 랭킹 창을 해 볼 것.
- **끝없는 탑 밸런스는 자동 조종 기준이다.** 일반 장비·강화 없이 Lv1 약 14층 · Lv9 약 21층 · Lv18 약 35층 · Lv36 약 62층, 한 층 40초쯤(Lv1 은 70초쯤으로 길다). 자동 조종은 예고를 다 피하고 층마다 체력이 10% 차서 높이 오른다 — 사람이 해 보고 `TOWER.heal` · 층 레벨(`towerLevel`) · 요괴 수(`floorCount`)를 맞출 것.
- **탑 화면은 PC 크롬(450×800)에서 시작 화면 · 1~2층 · 층 카드 · 끝 카드 · '너무 빠름' 거절만 봤다** (테스트 모드, 콘솔로 출구에 옮겨서). 보스 층 카드(계속/그만)와 체크포인트에서 시작하는 흐름은 화면으로 못 보고 단위 테스트·PGlite 로만 봤다. 층마다 Phaser 게임을 새로 만들어 넘어갈 때 잠깐 끊긴다.
- **탑에서 통신이 끊기면** 그 층 보고를 한 번 더 보내 보고 안 되면 판이 끝난다(그 층 보상과 그 층에서 쓴 물약 빠짐은 없던 일이 된다). 맵처럼 보관했다가 다시 보내지 않는다.
- **탑 도중에 앱을 닫으면** 그 판은 끝나지 않은 채로 남고(다음 탑을 시작할 때 닫힌다) 그 층에서 쓴 물약은 빠지지 않는다.
- **탑과 맵 판의 시간 겹침은 서버가 보지 않는다** (탑 안에서는 층마다 서버 시계로 본다).
- **로비 카드 그림은 임시다** (`shared/images/card-twelve.png` — 기존 그림 모음). 4~12지형 보스는 탑에서 기본 공격 패턴으로 먼저 나온다.
- **랭킹 창은 가짜 응답으로만 봤다** (뷰가 운영 DB 에 아직 없다). 레벨 탭 · 탑 탭의 줄 모양은 확인했다.
- **맵 도중에 앱을 닫으면** 그 판에서 쓴 물약은 빠지지 않는다 (판이 끝나지 않아 서버가 모른다).
- **아이폰은 PC 의 WebKit 으로만 봤다 (실제 기기 아님).** 확인한 것: 조이스틱 드래그 · 조이스틱 누른 채 공격 누르고 있기 · 그 상태에서 세 번째 손가락으로 스킬 1·2 · 고유 · 구르기 · 물약 · 공격을 떼도 조이스틱이 남는 것 · 왼손잡이 좌우 바뀜 · 음수 손가락 번호(-910542186) · 화면 전부(메인 · 설정 · 시작 장면 4장 · 대원 · 가방 · 장비 팝업 · 지도 · 지형 1~3 · 상점 사기/팔기 · 대장간 · 탑 시작/층/층 카드/보스 층 카드/끝 카드 · 전투 HUD · 보스 막대·대사 · 일시정지 · 결과 클리어/쓰러짐)을 393×852 와 375×667 에서. 노치·홈 바는 CSS 의 `env(safe-area-inset-*)` 를 59px/34px 로 바꿔치기해서 봤다.
  데스크톱 WebKit 이 못 보여 주는 것: 길게 누름·돋보기 같은 UIKit 제스처, 메모리 한도로 탭이 다시 열리는 것, 실제 프레임 속도(머리 없는 WebKit 은 화면 갱신이 초당 15~20번뿐이라 프레임 간격은 잴 수 없었다), 소리 · 진동, 사파리 주소창이 있는 화면 높이. 실제 아이폰에서 한 판 해 볼 것.
