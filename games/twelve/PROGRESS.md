# 시아열두길 — 진행 상황 (다음 단계를 맡는 사람이 먼저 읽을 것)

마지막 갱신: 2026-11-23 · **2차 작업 2부 끝: 8~12지형(6단계 끝)** — 12지형 96맵이 모두 열렸다 (맵 40개 · 새 요괴 다섯 · 보스 다섯 · 환경 효과 다섯 · 보스의 선물 · 엽전 값 손봄 · pace 12지형). 첫 공개분(PR #11)은 main 에 머지되어 운영에 있다.
남은 것: **최종보스(7단계)** · 어려움 모드(8단계 나머지) · 그림/소리(9단계) · 밸런스·실제 폰 확인(10단계). 지도에 '준비 중'으로 남은 것은 가운데 최종보스 버튼뿐이다 (어려움 모드는 아직 화면에 없다).
브랜치 `feature/twelve-2` (푸시하지 않음 — 메인 세션이 한다). main 의 079~087(PR #12) 위로 옮겼다(rebase). **`078_twelve.sql` 은 운영에 있으니 고치지 않는다.** 새 SQL 은 `089_twelve_full.sql` 하나에(아직 푸시 전이라 이어서 고쳐도 된다. 088 은 다른 작업이 맡아 두었고, 다른 번호는 만들지 않는다).

## 해 보기

```bash
cd games/twelve
npm run dev      # http://localhost:5297/games/twelve/?local=1
npm test         # 549개 (맵마다 끝까지 깨 보는 시험은 tests/play1~3 — 지형 넷씩)
npm run build
npm run gen      # src/data/maps/r01~r12.ts 다시 만들기 (맵 생성).  -- 5 6 = 그 지형만
npm run sqlgen   # src/data 의 숫자로 supabase/migrations/089_twelve_full.sql 의 표(gen 블록)를 다시 쓴다 (078 은 건드리지 않는다)
npm run pace     # 플레이 시간·레벨 곡선 표 (1~12지형, 4분쯤).  -- 4 = 4지형까지,  -- 12 1 = 지형 수·씨앗 수,  -- weapons = 무기 4종 비교
npm run tower    # 끝없는 탑을 자동 조종이 몇 층까지 오르는지 (레벨별, 30초쯤).  -- 5 = 씨앗 수
```

개발 옵션 (`?local=1` 뒤에): `&map=1-3`(바로 그 맵) · `&lv=50` · `&god=1`(무적) · `&all=1`(모두 열림) · `&hero=tiger` · `&weapon=bow`(가방의 그 종류 무기를 든다).
개발 옵션으로 하는 판은 저장하지 않는다. 테스트 모드에서는 콘솔의 `__twelve` 가 지금 판 상태(RunState)다.
테스트 모드의 기록은 `localStorage['sia-twelve-local-v2']` (지우면 처음부터. 엽전·장비를 넣어 보려면 이 값을 고친다).
PC 키: WASD/방향키 이동, J 공격, K·L 스킬, U 고유 스킬, 스페이스 구르기, 1·2 물약, Esc 일시정지.

## 서버 (078_twelve.sql + 089_twelve_full.sql)

- **078 은 운영에 있다. 고치지 않는다.** 2차 작업에서 바꾸는 함수·표는 089 에 `create or replace` 로 다시 정의한다(뒤 정의가 이긴다). 새 RPC(예: `twelve_set_mode`)나 최종보스 맵을 다루게 고친 `twelve_start` · `twelve_finish` 도 089 에 넣는다 — `tests/sql.test.ts` 의 `fn()` 은 두 파일을 합친 것에서 마지막 정의를 본다. 새 표·열이 필요하면 `create table if not exists` · `alter table … add column if not exists` 를 089 에 넣고, sql.test 의 '089 는 … create table 이 없다' 검사를 그에 맞게 고친다.

- **RPC:** `twelve_state()` · `twelve_start(map, mode, hero)` → `{run, seed}` · `twelve_finish(run, report)` → `{state, result}` · `twelve_set_hero` · `twelve_equip` · `twelve_unequip` · `twelve_lock` · `twelve_claim` · `twelve_sell` · `twelve_scrap` · `twelve_enhance` · `twelve_buy(what, n)`. 모두 `{…state}`(= `TwelveProfile` 모양)를 돌려준다.
- **끝없는 탑 RPC:** `twelve_tower_start(floor, hero)` → `{run, seed, base}` · `twelve_tower_floor(run, floor, time, potions)` → `{state, result: {floor, coins, stones, items, siaCoin, time, best}}` · `twelve_tower_end(run, potions)` → `{…state}`. 기록은 `twelve_tower`(최고 층 · 시간 · 레벨 · 대원 · 날짜 · 체크포인트 `cps`), 진행 중인 판은 `twelve_tower_runs`. 상태(`state.tower`)에 내 탑 기록이 들어 있다(없으면 null).
- **랭킹 뷰:** `twelve_level_ranking`(한 맵이라도 깬 사람) · `twelve_tower_ranking`(탑에 한 번이라도 들어간 사람). 누구나 읽는다 — 랭킹 창이 다른 게임처럼 뷰를 바로 읽는다.
- **화면이 보내는 것:** 종류별 잡은 수 · 정예 수 · 보스 · 시간 · 상자 · 쓰러진 횟수 · 쓴 물약. 경험치·엽전·드랍·확정 보정·열쇠·별·시아코인은 서버가 계산한다.
- **표는 손으로 고치지 않는다:** 089 의 `-- <gen:이름>` 블록은 `npm run sqlgen` 이 만든다 (078 의 블록은 옛 값 그대로 남는다 — 보지 않는다). `tests/sql.test.ts` 가 블록마다 대조하므로, `src/data` 숫자를 바꾸고 sqlgen 을 안 돌리면 테스트가 깨진다.
- **규칙이 두 곳에 있다:** `progress.ts`(checkReport · applyReport) · `drops.ts` · `rules.ts` · `tower.ts` ↔ `twelve_finish` 와 상점·대장간 · 탑 RPC. 한쪽을 바꾸면 다른 쪽도 바꾸고 아래 확인 도구를 돌릴 것.
- **맵 표에 줄이 있는 맵만 시작할 수 있다** (`_twelve_maps` — 지금 96줄 = 보통 모드 전부. 어려움 모드를 열면(`HARD_READY`) sqlgen 이 어려움 줄을 더한다). 상점 등급·탑의 레어 목록도 이 표에 맵이 있는 지형까지만 본다(`_twelve_shop_tier`).

### SQL 을 실제로 돌려 보기 (PGlite)

PGlite 는 저장소에 넣지 않았다 (`npm test` 에는 없다). 아무 폴더에 한 번 설치해 두고 쓴다.

```bash
mkdir ~/pg && cd ~/pg && npm init -y && npm i @electric-sql/pglite     # 한 번만
cd games/twelve
npx vite-node scripts/pg-expect.ts > ~/pg/expect.json                  # 기기 규칙으로 계산한 기대값
node scripts/pg-check.mjs ~/pg                                         # 001~087 + 089 적용 → 확인
```

마이그레이션 전체를 적용한 뒤 ① `_twelve_roll` = `roll` ② 권한(직접 쓰기·내부 함수 거절) ③ 시작·끝 검사(잠긴 맵, 최대치 초과, 너무 빠름, 겹침, 너무 늦음, 시아코인 조건) ④ **정해 둔 57단계(1지형 전부 → 보스 반복 → 쓰러짐 → 확정 보정 → 상점 → 대장간 → 가방 꽉 참 → 보관함)를 기기 규칙과 서버가 단계마다 같은 기록을 내는지** ⑤ 고양이(조건 → 구매 → 선택)를 본다. 2026-11-23 에 모두 통과했다.
순서를 더하려면 `scripts/pg-expect.ts` 에 `play(…)` · `rpc(…)` 줄을 더하면 된다.
6단계에서 맵·숫자를 바꾼 뒤(2026-11-23) 다시 돌려 63단계가 모두 맞는 것을 확인했다 (PGlite 는 임시 폴더에 설치해서 썼다).
끝없는 탑을 더한 뒤(2026-11-23): ⑥ **탑 시나리오 179단계**(시작 거절 → 층 보고의 거절(순서 · 최소 시간 · 서버 시간 · 물약 모양) → 10층 체크포인트 → 11층에서 시작(시간 더하기) → 더 빠른 체크포인트 → 끝내지 않고 새 판 → 20층 × 6판의 보상 판정)를 기기 규칙과 단계마다 맞춰 보고, ⑦ 새 계정으로 권한 · '들어가기만 해도 0층 기록' · 10층 시아코인(`sia_coin_logs` 의 `판:층`) · 탑 랭킹 뷰 · '탑만 한 사람은 레벨 랭킹에 없다'를 본다. 모두 242단계 · 확인 108개 통과.
4~7지형을 더한 뒤(2026-11-23, 089): 맨 끝에 ⑧ **2지형부터 준비된 마지막 지형까지 차례로 깨는 48판 + 그 지형 등급 무기 사기**를 더했다. 001~087 + 089 적용 → 모두 291단계 · 확인 109개 통과 (PGlite 는 스크래치패드의 `pg` 폴더). 준비 안 된 지형 검사는 `'8-1'` 로 바꿨다 — 8지형을 열면 `pg-check.mjs` 의 그 줄과 끝 기록 검사(`s-n7`)를 고친다.
8~12지형을 더한 뒤(2026-11-23, 089): main 의 079~087 이 들어와 **001~087 + 089** 를 적용한다(088 은 아직 없다). ⑧ 이 2~12지형 88판으로 늘었고, 끝에 9 · 10 · 12지형 보스를 한 번씩 더 잡아 **보스의 선물이 한 번만 나오는지**(결과의 `gift` 15 · 20 · 30 → 0)를 본다. 모두 334단계 · 확인 111개 통과. '준비 안 된 지형' 검사는 `'final'`(최종보스 맵 — 7단계에서 열면 `pg-check.mjs` 의 그 줄을 고친다) · `'13-1'`(없는 지형) · `'12-1'`(잠김)로 바꿨다.
탑 순서를 더하려면 `scripts/pg-expect.ts` 의 `towerStart(층, 씨앗)` · `towerClimb(층 수, 초)` · `towerFloor(…)` · `towerEnd()` 줄을 더한다.

## 다음 단계가 알아야 할 것

- **밸런스를 고칠 때:** 고칠 곳은 `economy.ts`(드랍 · 값) · `growth.ts`(`EXP_CURVE`) · `enemies.ts`/`bosses.ts`(체력 · exp · coin) · `mapgen.ts`(방 수 · 무리 크기 · `PAR`) · `regions.ts`(`mapScale`). 순서: 고친다 → (맵에 영향이 있으면) `npm run gen` → `npm run pace` 로 표 확인 → `npm run sqlgen` → `npm test` (`tests/balance.test.ts` 가 곡선·드랍·값의 큰 틀을 본다) → 될 수 있으면 pg-check.
  요괴 체력·종류를 바꾸면 별 시간(`par`)도 바뀌므로 `npm run gen` 을 잊지 말 것 (`tests/maps.test.ts` 가 '생성 결과와 같다'로 잡아 준다).
- **요괴·보스·환경을 더하는 자리 (12지형은 다 찼다 — 최종보스·어려움 모드에서 쓸 때):**
  - 요괴 행동: `enemies.ts` 의 `EnemyAi` + `sim.ts` 의 `stepEnemies`. 지금 14가지(melee · dasher · slam · ranged · leap · lurk · pull · spit · bomb · hex · bounce · rage · call · blaze). 예고 뒤에 일어나는 일은 `Warn.after`(+ `aux` · `aux2` · `r`)로 넘긴다 (`stepWarns`): dash · shoot · jump · pull · pool · boom · nova · trail · call.
  - 보스 공격: `bosses.ts` 의 `BossMove` + `sim.ts` 의 `bossAct`. 지금 15가지(slam · charge · cone · ring · barrage(+pool) · cross · leap · rake · nova · march · spiral · wave · sweep · scorch · cage). 최종보스는 이것들을 섞어 쓰면 된다 (염라대왕이 그렇게 한다).
  - 환경 효과: `balance.ts` 의 `ENV` + `sim.ts` 의 `stepEnv`(시간·자리만으로 — 무작위 금지) · 이동에 걸리는 것은 `playerSlow` · 보이는 거리는 `sightOf`. 느려지는 땅(`~`)에 거는 효과면 `tower.ts` 의 `towerFloor` 목록에도 넣는다(진흙 · 물길 · 독안개 · 불길).
  - 대원을 느리게 하는 것: `Player.slowT` · `slowMul` (요괴의 탄 `Shot.slowDur`). 땅에 남는 것: `Pool`(`fire` 면 붉게 그린다).
  - 불러낸 요괴: `Enemy.owner`(부른 요괴 번호) — `summoned` 라 처치 수·보상·드랍에 안 들어간다. 부른 요괴가 쓰러지면 같이 사라진다.
- **경험치 곡선 `EXP_CURVE = 130 × n^1.4`** 는 그대로다. 12지형 끝의 레벨이 최종보스 권장 레벨의 바탕이 된다(아래 pace 결과). 최종보스 맵(7단계)의 보상·권장 레벨을 정할 때 `npm run pace -- 12` 뒤에 최종보스 한 판을 더하는 식으로 `scripts/pace.ts` 를 넓히면 15시간 · Lv65 를 볼 수 있다.
- **`HP_RAMP`(Lv22~34) · `HP_RAMP2`(Lv38~44)** 는 요괴 체력 배율에 더해지는 값이고 끝없는 탑도 같은 식을 쓴다. 어려움 모드(Lv66~99)는 아직 재지 않았다 — 맵이 짧으면 세 번째 오름을 더한다.
- **엽전:** 상점 값·강화 값을 강철부터 올렸다(`LATE_TIER`). 자동 조종은 지형마다 고향 대원의 무기 종류로 갈아타며 새로 사서 강화하므로 엽전을 거의 다 쓴다 — 한 무기만 쓰는 사람은 남는다. 어려움 모드의 등급(천둥~여의, 등급 8~11)은 같은 식으로 값이 더 오른다(여의 +9 까지 무기 하나 194,400) — 어려움 모드 pace 를 만들 때 다시 본다.
- **어려움 모드:** `HARD_READY` 를 켜면 sqlgen 이 어려움 맵 줄도 만든다. 모드를 바꾸는 RPC(`twelve_set_mode`)와 화면은 아직 없다 (`profile.mode` 는 늘 `normal`). 열쇠·확정 보정·별·맵 기록은 이미 모드별로 저장한다.
- **최종보스:** 맵 id 는 `'final'` 로 약속했다 (`FINAL_MAP`, `_twelve_normal_done`, `_cat_progress_twelve`). 지금 `MapId` 타입·`parseMapId`·`_twelve_maps` 는 `'지형-맵'` 만 다루므로 7단계에서 넓혀야 한다. 열쇠 12개 검사도 그때. `twelve_finish` 는 이미 089 에 다시 정의돼 있으니 그 정의를 고치면 된다(`tests/sql.test.ts` 의 '089 는 078 의 함수를 같은 모양으로 다시 정의한다'가 RPC 의 권한 줄을 본다). 지도의 최종보스 버튼(`app.ts` 의 `.final`)이 '준비 중'으로 남은 마지막 자리다. 염라대왕의 마지막 한마디('봉인은 아직…')가 최종보스로 이어진다.

## 알려진 문제 · 아직 안 한 것

- **9지형부터는 권장 레벨에 못 미친 채로 간다** (12지형 끝 Lv63.8, 마지막 맵 권장 65 — PRD 성장 표대로다). 자동 조종은 안 쓰러지지만 사람에게는 12지형이 꽤 어려울 수 있다. 어려우면 `EXP_LATE.step`(지금 0.004)을 올리거나 지형 사냥을 한 바퀴 더 돌게 된다.
- **11 · 12지형의 맵이 길다** (한 판 평균 6.9 · 7.2분, 11-7 은 9.7분 · 요괴 200마리). 11지형은 뱃사공 망령이 불러내는 망자 때문에, 12지형은 권장 레벨보다 낮게 들어가서다. 별 시간은 그에 맞춰져 있다(11-7 14분).
- **환경 효과는 대원에게만 걸린다** (요괴는 졸지 않고, 미끄러지지 않고, 불바닥에서 다치지 않는다). 새벽빛도 달그림자처럼 요괴만 가린다(예고 범위·날아오는 것·작은 지도는 보인다).
- **졸음 꽃가루는 서서 쏘는 무기(활·부채)에 더 불리하다.** 구르면 바로 깨지만, 자동 조종 기준으로도 8지형은 고향 대원 양(부채)이 맵마다 물약을 4~5개 쓴다.
- **불러낸 망자는 보상이 없다** (처치 수·경험치·엽전·드랍에 안 들어간다). 망령을 먼저 쓰러뜨리면 사라지므로 손해는 아니지만, 망자만 잡고 있으면 시간만 간다 — 뱃사공 망령의 설명 글에 적어 두었다.
- **보스의 선물 줄(결과 화면)은 화면으로 못 봤다.** 기기 규칙 · 서버(PGlite) · 단위 시험으로만 확인했다. 대원 합류 카드와 같은 모양(`.new-hero`)을 쓴다.
- **시험이 길어졌다:** 96맵을 자동 조종으로 끝까지 깨 보는 시험(`tests/play1~3`)이 다른 작업으로 바쁜 기계에서 1분 넘게 걸렸다(그때 전체 `npm test` 는 40~70초. 한가할 때는 재지 못했다). 한 파일에 두었을 때는 바쁜 기계에서 vitest 가 'Timeout calling onTaskUpdate' 로 실패해서 셋으로 나눴다 — 배포(GitHub Actions)에서 느리면 `tests/play.ts` 의 맵을 지형마다 몇 개로 줄일 것.
- **밸런스는 자동 조종 기준이다.** 사람 시간은 '자동 조종 × 1.3 + 판마다 30초'로 어림했다. 실제로 해 보고 `scripts/pace.ts` 의 `HUMAN` 과 맵 길이를 다시 맞춰야 한다. 자동 조종이 쓰러지지 않아 '쓰러져서 다시 하는 시간'과 난이도는 표에 안 보인다.
- **지형의 첫 맵이 쉽다.** 앞 지형 보스를 잡고 오면 레벨이 권장보다 높아 2-1 · 3-1 · 5-1 · 7-1 은 2~4분에 끝난다. 그 맵의 별 시간도 넉넉하다(자동 조종의 2배).
- **엽전은 자동 조종 기준으로 맞췄다.** 강철부터 상점 값·강화 값을 올려 자동 조종은 12지형 끝에 6천쯤 남는다(고치기 전 19만). 자동 조종은 지형마다 무기 종류를 갈아타며 새로 사서 강화하므로, 무기 하나만 쓰는 사람은 더 남고 대원·무기를 자주 바꾸는 사람은 +9 를 다 못 올린다. 사람이 해 보고 `enhanceCost` 의 ÷2 · `buyPrice` 를 다시 볼 것. 상점 품목(강화석·장신구 팔기)은 더하지 않았다.
- **4~12지형은 자동 조종과 머리 없는 WebKit 으로만 봤다.** 사람이 해 보지 않았다: 그슨대가 얼마나 보이는지(불투명도 16~22%) · 달그림자 반지름(330px) · 물살 세기 · 독 피해 · 화살 간격 · 졸음이 쌓이는 빠르기(1초 뒤부터 2초) · 미끄러지는 거리(90px) · 새벽빛 간격과 보이는 거리(12초마다 3초 · 190px) · 찬 강바람(마력 ×0.65) · 화상(0.5초마다 1.5%)은 해 보고 맞춰야 한다(`ENV`). 보스의 새 공격 다섯(소용돌이 · 물결 · 낫 · 불숨 · 에워싸기)도 피하는 느낌을 사람 손으로 봐야 한다.
- **달그림자는 요괴만 가린다.** 날아오는 불·예고 범위·떨어진 것·작은 지도는 그대로 보인다. 작은 지도에 요괴 점이 있다면 그것도 그대로다.
- **물살·독은 대원에게만 걸린다** (요괴는 물에서 밀리지 않고 늪에서 다치지 않는다). 진흙·골바람과 같다.
- **끝없는 탑이 조금 어려워졌다.** `HP_RAMP` 와 4~7지형 보스의 새 공격 때문에 자동 조종 기준 Lv18 약 35 → 31층, Lv36 약 62 → 54층. 8~12지형을 더한 뒤 다시 재도 Lv1~36 의 층수는 같았다(Lv36 약 54층 — `npm run tower`). 그 위 레벨은 재지 않았다: 71층부터는 새 요괴·보스 공격·환경이 나온다.
- **화약 도깨비가 터져도 처치로 센다.** 가만히 맞아 주기만 해도 경험치·엽전을 받는다(체력이 낮고 수가 적어 큰 차이는 아니다). 서버 최대치·출구 조건과 어긋나지 않게 하려는 선택이다.
- **요괴가 150마리를 넘는 맵이 많다** (5~12지형의 4~7번 맵 150~181마리, 11-7 은 200마리 + 불러낸 망자). 성능은 위 'pace 결과 — 성능'에 적었다: 시뮬레이션은 넉넉하고, 화면(WebKit)은 기계가 바쁠 때만 재서 믿을 만한 숫자가 없다.
- **새 요괴 열하나는 기존 그림에 색만 입혔다** (진흙 요괴 = 물귀신 그림, 살쾡이 요괴 = 여우불, 그슨대 · 가위 귀신 · 뱃사공 망령 = 원혼, 메기 요괴 · 야차 = 방망이 도깨비, 독두꺼비 · 화약 도깨비 · 잔나비 요괴 = 꼬마 도깨비, 화차 = 도깨비불). 불러낸 망자는 작은 해골 병사다. 시작 장면도 기존 그림을 모은 것이다. 필요한 그림은 `ASSETS.md`.
- **골바람은 요괴를 밀지 않는다** (대원만). 진흙도 대원만 느려진다.
- **한꺼번에 팔기·분해**는 일반 무기·방어구만 한다 (착용 · 잠금 · 레어 · 장신구 · 강화한 것 · 종류마다 가장 좋은 무기 하나는 남긴다). 장신구는 하나씩 정리해야 한다.
- **정예를 보스보다 나중에 잡으면** 확정 보정 경계에서 전투 화면의 빛기둥과 결과가 다를 수 있다 (서버는 정예 → 보스 순서로 판정).
- **서버 RPC 를 진짜 Supabase 에서 불러 보지 않았다.** PGlite 확인과 `createSupabaseApi` 단위 테스트(가짜 RPC)만 했다. 게임은 닫혀 있으니, 배포 뒤 관리자 계정으로 맵 한 판 · 탑 몇 층 · 랭킹 창을 해 볼 것.
- **끝없는 탑 밸런스는 자동 조종 기준이다.** 일반 장비·강화 없이 Lv1 약 14층 · Lv9 약 21층 · Lv18 약 35층 · Lv36 약 62층, 한 층 40초쯤(Lv1 은 70초쯤으로 길다). 자동 조종은 예고를 다 피하고 층마다 체력이 10% 차서 높이 오른다 — 사람이 해 보고 `TOWER.heal` · 층 레벨(`towerLevel`) · 요괴 수(`floorCount`)를 맞출 것.
- **탑 화면은 PC 크롬(450×800)에서 시작 화면 · 1~2층 · 층 카드 · 끝 카드 · '너무 빠름' 거절만 봤다** (테스트 모드, 콘솔로 출구에 옮겨서). 보스 층 카드(계속/그만)와 체크포인트에서 시작하는 흐름은 화면으로 못 보고 단위 테스트·PGlite 로만 봤다. 층마다 Phaser 게임을 새로 만들어 넘어갈 때 잠깐 끊긴다.
- **탑에서 통신이 끊기면** 그 층 보고를 한 번 더 보내 보고 안 되면 판이 끝난다(그 층 보상과 그 층에서 쓴 물약 빠짐은 없던 일이 된다). 맵처럼 보관했다가 다시 보내지 않는다.
- **탑 도중에 앱을 닫으면** 그 판은 끝나지 않은 채로 남고(다음 탑을 시작할 때 닫힌다) 그 층에서 쓴 물약은 빠지지 않는다.
- **탑과 맵 판의 시간 겹침은 서버가 보지 않는다** (탑 안에서는 층마다 서버 시계로 본다).
- **로비 카드 그림은 임시다** (`shared/images/card-twelve.png` — 기존 그림 모음). 탑에서는 아직 지도에서 못 만난 지형의 보스도 먼저 나온다(그 보스의 공격 패턴 그대로).
- **랭킹 창은 가짜 응답으로만 봤다** (뷰가 운영 DB 에 아직 없다). 레벨 탭 · 탑 탭의 줄 모양은 확인했다.
- **맵 도중에 앱을 닫으면** 그 판에서 쓴 물약은 빠지지 않는다 (판이 끝나지 않아 서버가 모른다).
- **아이폰은 PC 의 WebKit 으로만 봤다 (실제 기기 아님).** 확인한 것: 조이스틱 드래그 · 조이스틱 누른 채 공격 누르고 있기 · 그 상태에서 세 번째 손가락으로 스킬 1·2 · 고유 · 구르기 · 물약 · 공격을 떼도 조이스틱이 남는 것 · 왼손잡이 좌우 바뀜 · 음수 손가락 번호(-910542186) · 화면 전부(메인 · 설정 · 시작 장면 4장 · 대원 · 가방 · 장비 팝업 · 지도 · 지형 1~3 · 상점 사기/팔기 · 대장간 · 탑 시작/층/층 카드/보스 층 카드/끝 카드 · 전투 HUD · 보스 막대·대사 · 일시정지 · 결과 클리어/쓰러짐)을 393×852 와 375×667 에서. 노치·홈 바는 CSS 의 `env(safe-area-inset-*)` 를 59px/34px 로 바꿔치기해서 봤다.
  데스크톱 WebKit 이 못 보여 주는 것: 길게 누름·돋보기 같은 UIKit 제스처, 메모리 한도로 탭이 다시 열리는 것, 실제 프레임 속도(머리 없는 WebKit 은 화면 갱신이 초당 15~20번뿐이라 프레임 간격은 잴 수 없었다), 소리 · 진동, 사파리 주소창이 있는 화면 높이. 실제 아이폰에서 한 판 해 볼 것.
