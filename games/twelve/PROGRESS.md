# 시아열두길 — 진행 상황 (다음 단계를 맡는 사람이 먼저 읽을 것)

마지막 갱신: 2026-11-23 · **10단계(아이폰 WebKit 확인) 끝 — 4~12지형·최종보스·어려움 모드·탑 화면을 두 크기에서 보고 고쳤다(아래 '10단계').** 그 앞: **2차 작업 5부: 그림·소리(9단계) — 그림은 크레딧이 없어 일부만.** SpriteCook 크레딧이 2개뿐이라 최종보스 어둑시니 `b-final` 한 장만 만들었고(남은 크레딧 0), 지형 바닥 12종은 시아핑거의 그림을 복사해 넣었다. 소리 6개(`twelve*`)를 `shared/sound.js` 에 더했다. 첫 공개분(PR #11)은 main 에 머지되어 운영에 있다.
남은 것: **그림 대부분(대원 걷기·공격 시트 · 지형 전용 요괴 · 장비 아이콘 · 효과 · 장면 · 로비 카드 — `ASSETS.md` 의 '9단계 결과'와 ✅ 없는 줄)** — 크레딧을 채운 뒤 · 실제 아이폰에서 한 판 해 보기(PC WebKit 으로는 다 봤다). '준비 중'으로 남은 것은 없다.
브랜치 `feature/twelve-2` (푸시하지 않음 — 메인 세션이 한다). main 의 079~087(PR #12) 위로 옮겼다(rebase). **`078_twelve.sql` 은 운영에 있으니 고치지 않는다.** 새 SQL 은 `094_twelve_full.sql` 하나에(아직 푸시 전이라 이어서 고쳐도 된다. 088 은 다른 작업이 맡아 두었고, 다른 번호는 만들지 않는다).

개발 옵션으로 하는 판은 저장하지 않는다. 테스트 모드에서는 콘솔의 `__twelve` 가 지금 판 상태(RunState)다.
테스트 모드의 기록은 `localStorage['sia-twelve-local-v2']` (지우면 처음부터. 엽전·장비를 넣어 보려면 이 값을 고친다).
PC 키: WASD/방향키 이동, J 공격, K·L 스킬, U 고유 스킬, 스페이스 구르기, 1·2 물약, Esc 일시정지.

## 서버 (078_twelve.sql + 094_twelve_full.sql)

- **078 은 운영에 있다. 고치지 않는다.** 2차 작업에서 바꾸는 함수·표는 094 에 `create or replace` 로 다시 정의한다(뒤 정의가 이긴다). 새 RPC(예: `twelve_set_mode`)나 최종보스 맵을 다루게 고친 `twelve_start` · `twelve_finish` 도 094 에 넣는다 — `tests/sql.test.ts` 의 `fn()` 은 두 파일을 합친 것에서 마지막 정의를 본다. 새 표·열이 필요하면 `create table if not exists` · `alter table … add column if not exists` 를 094 에 넣고, sql.test 의 '094 는 … create table 이 없다' 검사를 그에 맞게 고친다.

- **RPC:** `twelve_state()` · `twelve_start(map, mode, hero)` → `{run, seed}` · `twelve_finish(run, report)` → `{state, result}` · `twelve_set_mode(mode)`(094 — 어려움은 보통 모드를 끝낸 뒤, 아니면 `'mode locked'`) · `twelve_set_hero` · `twelve_equip` · `twelve_unequip` · `twelve_lock` · `twelve_claim` · `twelve_sell` · `twelve_scrap` · `twelve_enhance` · `twelve_buy(what, n)`. 모두 `{…state}`(= `TwelveProfile` 모양)를 돌려준다.
- **끝없는 탑 RPC:** `twelve_tower_start(floor, hero)` → `{run, seed, base}` · `twelve_tower_floor(run, floor, time, potions)` → `{state, result: {floor, coins, stones, items, siaCoin, time, best}}` · `twelve_tower_end(run, potions)` → `{…state}`. 기록은 `twelve_tower`(최고 층 · 시간 · 레벨 · 대원 · 날짜 · 체크포인트 `cps`), 진행 중인 판은 `twelve_tower_runs`. 상태(`state.tower`)에 내 탑 기록이 들어 있다(없으면 null).
- **랭킹 뷰:** `twelve_level_ranking`(한 맵이라도 깬 사람) · `twelve_tower_ranking`(탑에 한 번이라도 들어간 사람). 누구나 읽는다 — 랭킹 창이 다른 게임처럼 뷰를 바로 읽는다.
- **화면이 보내는 것:** 종류별 잡은 수 · 정예 수 · 보스 · 시간 · 상자 · 쓰러진 횟수 · 쓴 물약. 경험치·엽전·드랍·확정 보정·열쇠·별·시아코인은 서버가 계산한다.
- **표는 손으로 고치지 않는다:** 094 의 `-- <gen:이름>` 블록은 `npm run sqlgen` 이 만든다 (078 의 블록은 옛 값 그대로 남는다 — 보지 않는다). `tests/sql.test.ts` 가 블록마다 대조하므로, `src/data` 숫자를 바꾸고 sqlgen 을 안 돌리면 테스트가 깨진다.
- **규칙이 두 곳에 있다:** `progress.ts`(checkReport · applyReport) · `drops.ts` · `rules.ts` · `tower.ts` ↔ `twelve_finish` 와 상점·대장간 · 탑 RPC. 한쪽을 바꾸면 다른 쪽도 바꾸고 아래 확인 도구를 돌릴 것.
- **맵 표에 줄이 있는 맵만 시작할 수 있다** (`_twelve_maps` — 194줄 = (지형 맵 96 + 최종보스맵 `'final'` = 12지형의 9번째 줄) × 보통·어려움. 권장 레벨 · 별 시간 · 요괴 수 · 보상이 모드마다 다르다). 상점 등급·탑의 레어 목록도 이 표에 맵이 있는 지형까지만 본다(`_twelve_shop_tier`).

### SQL 을 실제로 돌려 보기 (PGlite)

PGlite 는 저장소에 넣지 않았다 (`npm test` 에는 없다). 아무 폴더에 한 번 설치해 두고 쓴다.

```bash
mkdir ~/pg && cd ~/pg && npm init -y && npm i @electric-sql/pglite     # 한 번만
cd games/twelve
npx vite-node scripts/pg-expect.ts > ~/pg/expect.json                  # 기기 규칙으로 계산한 기대값
node scripts/pg-check.mjs ~/pg                                         # 001~094 적용 → 확인
```

마이그레이션 전체를 적용한 뒤 ① `_twelve_roll` = `roll` ② 권한(직접 쓰기·내부 함수 거절) ③ 시작·끝 검사(잠긴 맵, 최대치 초과, 너무 빠름, 겹침, 너무 늦음, 시아코인 조건) ④ **정해 둔 57단계(1지형 전부 → 보스 반복 → 쓰러짐 → 확정 보정 → 상점 → 대장간 → 가방 꽉 참 → 보관함)를 기기 규칙과 서버가 단계마다 같은 기록을 내는지** ⑤ 고양이(조건 → 구매 → 선택)를 본다. 2026-11-23 에 모두 통과했다.
순서를 더하려면 `scripts/pg-expect.ts` 에 `play(…)` · `rpc(…)` 줄을 더하면 된다.
6단계에서 맵·숫자를 바꾼 뒤(2026-11-23) 다시 돌려 63단계가 모두 맞는 것을 확인했다 (PGlite 는 임시 폴더에 설치해서 썼다).
끝없는 탑을 더한 뒤(2026-11-23): ⑥ **탑 시나리오 179단계**(시작 거절 → 층 보고의 거절(순서 · 최소 시간 · 서버 시간 · 물약 모양) → 10층 체크포인트 → 11층에서 시작(시간 더하기) → 더 빠른 체크포인트 → 끝내지 않고 새 판 → 20층 × 6판의 보상 판정)를 기기 규칙과 단계마다 맞춰 보고, ⑦ 새 계정으로 권한 · '들어가기만 해도 0층 기록' · 10층 시아코인(`sia_coin_logs` 의 `판:층`) · 탑 랭킹 뷰 · '탑만 한 사람은 레벨 랭킹에 없다'를 본다. 모두 242단계 · 확인 108개 통과.

  - 환경 효과: `balance.ts` 의 `ENV` + `sim.ts` 의 `stepEnv`(시간·자리만으로 — 무작위 금지) · 이동에 걸리는 것은 `playerSlow` · 보이는 거리는 `sightOf`. 느려지는 땅(`~`)에 거는 효과면 `tower.ts` 의 `towerFloor` 목록에도 넣는다(진흙 · 물길 · 독안개 · 불길).
  - 대원을 느리게 하는 것: `Player.slowT` · `slowMul` (요괴의 탄 `Shot.slowDur`). 땅에 남는 것: `Pool`(`fire` 면 붉게 그린다).
  - 불러낸 요괴: `Enemy.owner`(부른 요괴 번호) — `summoned` 라 처치 수·보상·드랍에 안 들어간다. 부른 요괴가 쓰러지면 같이 사라진다.
- **경험치 곡선 `EXP_CURVE = 130 × n^1.4`** 는 그대로다. `npm run pace -- 12` 는 12지형 뒤에 최종보스 몫(채비 사냥 한 바퀴 + 최종보스맵)을 붙여 보통 모드 전체(15.08시간 · Lv65.8)를 낸다. 어려움 모드는 이 끝(Lv65~66 · 흑철 레어 +9 또는 비취)에서 시작한다. **Lv66 부터는 `EXP_HARD` 로 필요한 경험치가 더 가파르다**(어려움 모드의 곡선 — 보통 모드 결과에는 영향이 없다).
- **`HP_RAMP`(Lv22~34) · `HP_RAMP2`(Lv38~44)** 는 요괴 체력 배율에 더해지는 값이고 끝없는 탑도 같은 식을 쓴다. 어려움 모드(Lv66~99)는 이 식 위에 `HARD.hp`(×1.15~1.35)를 곱한다 — 맵 한 판 평균 5.4분.
- **엽전:** 상점 값·강화 값을 강철부터 올렸다(`LATE_TIER`). 자동 조종은 지형마다 고향 대원의 무기 종류로 갈아타며 새로 사서 강화하므로 엽전을 거의 다 쓴다 — 한 무기만 쓰는 사람은 남는다. 어려움 모드의 등급(천둥~여의, 등급 8~11)은 같은 식으로 값이 더 오른다(여의 +9 까지 무기 하나 194,400) — 어려움 pace 에서는 무기 하나를 등급이 오를 때만 바꾸는 가정으로 엽전이 100만쯤 남고, 지형마다 종류를 갈아타는 가정으로는 여의를 못 샀다(아래 '알려진 문제').
- **어려움 모드를 고칠 때:** 숫자는 `regions.ts` 의 `HARD`(무리 수 `count` · 체력 `hp` + `hpStep` · 공격 `atk` · 별 시간 `par` · 최종보스맵 `final`)와 `growth.ts` 의 `EXP_HARD`(Lv66 부터의 곡선). 고친 뒤 `PACE_CACHE=… npm run pace -- hard` → `npm run sqlgen` → `npm test` → pg-check. `count` 를 바꾸면 맵 표의 최대 처치 수가 바뀐다(서버 검사). 보통 모드의 숫자(`HP_RAMP` · `EXP_LATE` · 요괴·보스 능력치 · 맵)를 바꾸면 어려움도 같이 움직이니 `npm run pace` 전체를 다시 볼 것.
  - **모드를 보는 자리:** 화면은 `profile.mode` 하나로 간다(`progress.ts` 함수들의 기본 인자가 `p.mode`). 모드 잠김은 `modeOpen` 한 곳(↔ 서버 `_twelve_normal_done` 을 보는 `_twelve_region_open` · `twelve_start` · `twelve_set_mode`). 판의 모드는 `RunState.mode` — 결과 화면·별 시간은 판의 모드를 쓴다.
  - **끝없는 탑의 판은 늘 `'normal'`** 이다 (`app.ts` 의 `playFloor`). 탑에 어려움 공격을 넣고 싶으면 서버의 최소 시간·랭킹이 모드와 상관없다는 점부터 다시 정해야 한다.
  - **진짜 엔딩** 장면은 `app.ts` 의 `TRUE_ENDING`(전용 그림 이름 `finale-1~4`). `showResult` 는 '그 모드에서 처음 깬 최종보스'면 판의 모드에 맞는 엔딩을 띄운다.
  - 어둑시니의 어려움 공격은 `hardMoves`(무너지는 봉인 49칸) 하나다. 단계는 `BossDef.phases` — 다른 보스에 단계를 주고 싶으면 같은 식으로 넣으면 된다(`sim.ts` 의 `bossAct` 가 처리한다).
- **최종보스맵을 고칠 때:** 맵은 `src/data/maps/final.ts`(손으로 — `npm run gen` 과 상관없다. 별 시간 `par` 도 손으로: 지금 720초 = 사람이 깬 시간의 1.35배), 보스는 `bosses.ts` 의 `eoduksini`. 고친 뒤 `PACE_CACHE=… npm run pace -- final` → `npm run sqlgen` → `npm test`. `final` 은 `region 12 · no 9` 라서 `map.region` 으로 지형 것을 찾는 코드는 12지형 것을 얻는다 — 보스·환경·고향은 꼭 `bossIdOf` · `envOf` · `homeRegionOf` 로.
- **열쇠는 지형 번호 순서로 둔다** (`applyReport` 가 정렬한다 — 서버가 주는 모양과 같게. 보스를 다시 잡아 뒤늦게 얻은 열쇠 때문에 PGlite 대조에서 드러났다).
- **끝없는 탑을 고칠 때:** 숫자는 `src/data/tower.ts` 의 `TOWER` → `npm run sqlgen`(기준 값 `tower_*`) → `npm test`. 규칙(보상 순서 · 검사)을 바꾸면 `src/game/tower.ts` 와 078 의 `twelve_tower_floor` 를 같이 바꾸고 pg-check 를 돌린다. 방 모양·요괴 구성은 서버와 상관없다(`towerFloor`). `npm run tower` 로 오르는 층을 본다.
- **탑의 층 = 맵과 같은 `MapDef`** (`tower: 층`, id `0-<층>`, 숨은 상자 없음). `mapOf('0-5')` 는 null 이므로 탑의 방에 맵용 함수(`mapReward` · `checkReport`)를 쓰지 말 것. 4지형부터 환경 효과를 더하면 탑의 그 지형 층(31층~)에도 걸린다 — 방에 그 효과가 걸리는 땅이 필요하면 `towerFloor` 에 더한다(지금은 진흙만).
- **지형을 더 열면(REGIONS_READY)** 탑의 장비 등급과 레어 목록이 따라 늘어난다 (`shopTier` · `towerRareLists` ↔ `_twelve_shop_tier` · `twelve_tower_floor`). 어려움 지형의 등급·레어도 같은 규칙으로 들어온다(보통 모드를 끝내면 어려움 1지형부터).
- **랭킹 창(`shared/ranking-dialog.js`)은 모든 게임이 같이 쓴다.** 열두길 탭은 `TWELVE_MODES` · `getTwelveRanking` · `showTwelve`. 지형 이름 `TWELVE_REGIONS` 는 `regions.ts` 의 이름을 옮겨 적은 것이라 이름을 바꾸면 같이 고친다. 게임 화면의 CSS 클래스가 창의 클래스(`.note` · `.tabs` · `.list` · `.modes` · `.subs`)와 겹치지 않게 할 것 — HUD 알림을 `.note` 로 뒀다가 창의 설명 줄이 화면 위로 떠서 `.hud-note` 로 바꿨다.
- **로비에서 여는 법:** 관리자 계정으로 로비의 오픈 설정에서 '시아열두길'을 켠다. 닫혀 있는 동안에도 관리자는 들어갈 수 있고, 게임 안의 랭킹 버튼은 열두길 탭만 보여 준다. `shared/characters.js` 의 `CHARACTER_GAMES` 와 071 의 `_character_games` 에는 이미 `'twelve'` 가 있다.
- **고양이:** 보통 모드를 끝내기 전에는 어디에도 보이지 않는다. 끝낸 뒤 쉼터의 등장 장면(`showCatScene`, 기기마다 한 번 — `siatwelve:cat-scene`) · 쉼터의 '야옹이가 기다려요' 줄 · 대원 화면의 '시아코인 100개로 열기'가 모두 `buyCat()` 으로 간다 (조건·값 확인 창 → `buyCharacter('cat')` → 071 의 `buy_character('twelve','cat')`, 조건은 078 의 `_cat_progress_twelve`). 테스트 모드는 `buyLocalCat()` 으로 흉내만 낸다. **진짜 서버에서의 구매는 해 보지 않았다**(PGlite 와 테스트 모드만).
- **레어 효과 더하기:** `economy.ts` 의 `FX` 에 숫자, `sim.ts` 의 `hitEnemy`(무기) · `hurtPlayer`(방어구)에 동작, `items.ts` 의 `FX_NAME` · `FX_DESC`. 방어구 '수호'는 지형 환경 효과를 절반만 받는다(`FX.ward.env` → `RunState.env.f`).
- **전투 화면의 드랍은 미리보기다.** 서버가 준 씨앗으로 같은 규칙을 돌려 보여 주고, 실제로 받는 것은 `twelve_finish` 의 결과다(결과 화면). 개발 판·통신 실패 판은 기기 씨앗이라 저장되지 않는다.
- **성능:** 드랍 그림 글자(Text)는 떨어질 때 한 번 만들고 주우면 지운다. 프레임마다 새로 만들지 말 것.
- **전투 화면 높이는 기기마다 다르다** (720×1280~1600). `GameScene` 안에서 화면 높이는 `this.vh`, 카메라 세로는 `camTargetY()` 를 쓴다. 시뮬레이션(`sim.ts`)은 화면 크기를 모른다 — 요괴가 깨어나는 거리 등은 그대로다. 새 버튼·줄을 만들 때 누르는 것은 44px 이상(`.btn.small` 은 이미 `min-height: 44px`).
- **아이폰 WebKit 으로 다시 볼 때:** 메모리 노트 'ios-webkit-testing' 의 방법(playwright-core@1.65.1 + `webkit-2388`, `Input.dispatchTouchEvent` 로 손가락 여러 개). `window.__twelve`(판 상태) · `window.__twelveGame`(Phaser.Game)으로 요괴를 모으거나 판을 끝내고(`__twelve.phase = 'clear'`) 화면을 넘긴다.

- **가정 (어려움):** 지형마다 6·7번 맵 두 바퀴 · 무기는 등급이 오를 때만 새로 산다(지형마다 종류를 갈아타지 않는다 — 고향 대원의 무기 종류가 아니어도 든다) · 안 쓰는 장비는 강화석 40개가 모일 때까지 분해. 보통 모드의 가정(지형마다 갈아타기)은 그대로다.
- **지형을 끝낼 때의 레벨 − 마지막 맵 권장 레벨:** −0.4 ~ +1.9 (2지형 −0.4 · 5지형 −0.1 · 그 밖은 +0~+2). 권장 레벨과 거의 나란히 간다.

- **별 시간 ÷ 사람이 깬 시간** (`PACE_PAR=1`, 별 시간 ×1.3 기준): 어려움은 가장 빡빡한 맵이 1.6쯤.
- **이번에 고친 숫자:** `HARD`(새로) · `EXP_HARD`(새로). 보통 모드의 표는 숫자 하나 안 바뀌었다(15.08시간 · Lv65.8).

## 알려진 문제 · 아직 안 한 것

- **어려움 모드는 자동 조종과 머리 없는 WebKit 으로만 봤다.** 자동 조종은 예고를 다 피해서 어려움 맵에서 한 번도 안 쓰러진다 — 공격 ×1.35 · 요괴 수 ×1.3 이 사람에게 얼마나 어려운지는 해 봐야 안다(`HARD.atk` · `HARD.count`). 보스의 어려움 공격 13가지(`hardMoves`)도 피하는 느낌을 사람 손으로 보지 않았다.
- **어려움의 엽전이 남는다** (무기 하나만 쓰면 끝에 100만쯤 — 위 'pace 결과 — 어려움 모드'). 반대로 무기 종류를 자주 바꾸면 여의(Lv99)를 못 산다. 등급 8~11 의 값은 사람이 해 본 뒤 다시 맞출 것.
- **장비가 한 박자 늦다:** 어려움 1~3지형은 Lv72 장비가 떨어지지만 Lv72 는 3지형쯤에 된다(1~2지형은 보통 모드의 비취로 간다). 10~12지형의 여의(Lv99)는 어려움을 거의 끝낼 때에야 든다 — PRD 의 등급 표 그대로다. 어색하면 `REGION_TIER.hard` 를 한 칸씩 늦춘다(sqlgen · pg-check).
- **어려움 최종보스는 가까이 붙는 무기에 더 어렵다** (보통 모드와 같다). 여의 +9 · 물약 소 8개만 든 자동 조종은 칼로 6번 중 0번, 창 2번, 활 5번, 부채 3번 깼다(큰 물약을 들면 더 잘 깬다 — pace 에서는 평균 0.7번 쓰러지고 깬다). Lv99 · 여의가 끝이라 더 클 수 없으니, 사람이 못 깨면 `HARD.final` 을 낮춘다.
- **어려움 보스는 색 변형이 없다** (PRD '어려움은 색 변형' — 9단계 그림 작업). 진짜 엔딩 4장도 기존 그림 모음이다(`finale-1~4` — `ASSETS.md`).
- **모드 표시는 제목 옆 작은 글자뿐이다** (지도 '🔥 어려움' · 지형 '🔥'). 전투 화면에는 모드 표시가 없다(권장 레벨로만 안다).
- **진짜 서버에서 모드 전환·어려움 판을 해 보지 않았다** (PGlite · 테스트 모드만). 배포 뒤 관리자 계정으로 볼 때 빨리 보려면 운영 DB 의 `twelve_maps` 에 `('normal','final')` 줄을 넣는다.
- **개발 옵션으로 볼 때는 모드 전환 버튼이 안내만 띄운다** (`&mode=hard` 로 본다 — 개발 판은 저장하지 않아서다).

- **최종보스는 자동 조종과 머리 없는 WebKit 으로만 봤다.** 사람이 싸워 보지 않았다: 열두 시의 줄 간격(0.09~0.14초)과 무너지는 봉인의 틈(칸 170px · 원 반지름 84px · 0.8~0.9초)이 피할 만한지, 세 단계의 길이(체력 9000)가 지루하지 않은지 해 보고 맞춰야 한다. 자동 조종은 칼·창으로 3단계에서 자주 쓰러지고 활·부채로는 쉽게 깬다 — 가까이 붙는 무기에 더 어렵다.
- **무너지는 봉인은 먼저 터지는 칸과 나중 칸이 색으로 구분되지 않는다** (차오르는 빠르기만 다르다). 헷갈리면 나중 칸의 예고를 늦게 보이게(`Warn.delay`) 바꾸는 쪽이 낫다.
- **어둑시니 그림은 야광귀 그림을 크게 쓴 것이다** (8지형 보스와 같은 모습). 엔딩 4장 · 고양이 장면도 기존 그림 모음이다 — `ASSETS.md`.
- **최종보스맵의 별 시간(12분)은 손으로 정했다** (자동 조종이 깬 판 × 1.3 의 1.35배). 맵을 고치면 같이 고친다.
- **엔딩은 처음 깬 판의 결과 화면에서만 이어진다.** 결과를 서버에 못 보낸 판(통신 실패 → 다음에 다시 보냄)에서는 엔딩이 뜨지 않는다 — 설정의 '엔딩 다시 보기'로 볼 수 있다. 고양이 장면은 기기마다 한 번(`localStorage`)이라 다른 기기에서는 다시 뜬다(이미 샀으면 안 뜬다).
- **진짜 서버에서 최종보스맵 · 고양이 구매를 해 보지 않았다** (PGlite · 테스트 모드만). 배포 뒤 관리자 계정으로 열쇠 12개 뒤 흐름을 한 번 볼 것 — 운영 DB 에서 빨리 보려면 `twelve_maps` · `twelve_keys` 에 줄을 넣는다.

- **9지형부터는 권장 레벨에 못 미친 채로 간다** (12지형 끝 Lv63.8, 마지막 맵 권장 65 — PRD 성장 표대로다). 자동 조종은 안 쓰러지지만 사람에게는 12지형이 꽤 어려울 수 있다. 어려우면 `EXP_LATE.step`(지금 0.004)을 올리거나 지형 사냥을 한 바퀴 더 돌게 된다.
- **11 · 12지형의 맵이 길다** (한 판 평균 6.9 · 7.2분, 11-7 은 9.7분 · 요괴 200마리). 11지형은 뱃사공 망령이 불러내는 망자 때문에, 12지형은 권장 레벨보다 낮게 들어가서다. 별 시간은 그에 맞춰져 있다(11-7 14분).
- **환경 효과는 대원에게만 걸린다** (요괴는 졸지 않고, 미끄러지지 않고, 불바닥에서 다치지 않는다). 새벽빛도 달그림자처럼 요괴만 가린다(예고 범위·날아오는 것·작은 지도는 보인다).
- **졸음 꽃가루는 서서 쏘는 무기(활·부채)에 더 불리하다.** 구르면 바로 깨지만, 자동 조종 기준으로도 8지형은 고향 대원 양(부채)이 맵마다 물약을 4~5개 쓴다.
- **불러낸 망자는 보상이 없다** (처치 수·경험치·엽전·드랍에 안 들어간다). 망령을 먼저 쓰러뜨리면 사라지므로 손해는 아니지만, 망자만 잡고 있으면 시간만 간다 — 뱃사공 망령의 설명 글에 적어 두었다.
- **보스의 선물 줄(결과 화면)은 화면으로 못 봤다.** 기기 규칙 · 서버(PGlite) · 단위 시험으로만 확인했다. 대원 합류 카드와 같은 모양(`.new-hero`)을 쓴다.
- **시험이 길어졌다:** 96맵을 자동 조종으로 끝까지 깨 보는 시험(`tests/play1~3`)이 다른 작업으로 바쁜 기계에서 1분 넘게 걸렸다(그때 전체 `npm test` 는 40~70초. 한가할 때는 재지 못했다). 한 파일에 두었을 때는 바쁜 기계에서 vitest 가 'Timeout calling onTaskUpdate' 로 실패해서 셋으로 나눴다 — 배포(GitHub Actions)에서 느리면 `tests/play.ts` 의 맵을 지형마다 몇 개로 줄일 것.
- **밸런스는 자동 조종 기준이다.** 사람 시간은 '자동 조종 × 1.3 + 판마다 30초'로 어림했다. 실제로 해 보고 `scripts/pace.ts` 의 `HUMAN` 과 맵 길이를 다시 맞춰야 한다. 자동 조종이 쓰러지지 않아 '쓰러져서 다시 하는 시간'과 난이도는 표에 안 보인다.
- **지형의 첫 맵이 쉽다.** 앞 지형 보스를 잡고 오면 레벨이 권장보다 높아 2-1 · 3-1 · 5-1 · 7-1 은 2~4분에 끝난다. 그 맵의 별 시간도 넉넉하다(자동 조종의 2배).
- **엽전은 자동 조종 기준으로 맞췄다.** 강철부터 상점 값·강화 값을 올려 자동 조종은 12지형 끝에 6천쯤 남는다(고치기 전 19만). 자동 조종은 지형마다 무기 종류를 갈아타며 새로 사서 강화하므로, 무기 하나만 쓰는 사람은 더 남고 대원·무기를 자주 바꾸는 사람은 +9 를 다 못 올린다. 사람이 해 보고 `enhanceCost` 의 ÷2 · `buyPrice` 를 다시 볼 것. 상점 품목(강화석·장신구 팔기)은 더하지 않았다.
- **4~12지형은 자동 조종과 머리 없는 WebKit 으로만 봤다.** 사람이 해 보지 않았다: 그슨대가 얼마나 보이는지(불투명도 16~22%) · 달그림자 반지름(330px) · 물살 세기 · 독 피해 · 화살 간격 · 졸음이 쌓이는 빠르기(1초 뒤부터 2초) · 미끄러지는 거리(90px) · 새벽빛 간격과 보이는 거리(12초마다 3초 · 190px) · 찬 강바람(마력 ×0.65) · 화상(0.5초마다 1.5%)은 해 보고 맞춰야 한다(`ENV`). 보스의 새 공격 다섯(소용돌이 · 물결 · 낫 · 불숨 · 에워싸기)도 피하는 느낌을 사람 손으로 봐야 한다.
- **달그림자는 요괴만 가린다.** 날아오는 불·예고 범위·떨어진 것·작은 지도는 그대로 보인다. 작은 지도에 요괴 점이 있다면 그것도 그대로다.
- **물살·독은 대원에게만 걸린다** (요괴는 물에서 밀리지 않고 늪에서 다치지 않는다). 진흙·골바람과 같다.
- **끝없는 탑이 조금 어려워졌다.** `HP_RAMP` 와 4~7지형 보스의 새 공격 때문에 자동 조종 기준 Lv18 약 35 → 31층, Lv36 약 62 → 54층. 8~12지형을 더한 뒤 다시 재도 Lv1~36 의 층수는 같았다(Lv36 약 54층 — `npm run tower`). 그 위 레벨은 재지 않았다: 71층부터는 새 요괴·보스 공격·환경이 나온다.

- **요괴가 150마리를 넘는 맵이 많다** (5~12지형의 4~7번 맵 150~181마리, 11-7 은 200마리 + 불러낸 망자). 성능은 위 'pace 결과 — 성능'에 적었다: 시뮬레이션은 넉넉하고, 화면(WebKit)은 기계가 바쁠 때만 재서 믿을 만한 숫자가 없다.
- **새 요괴 열하나는 기존 그림에 색만 입혔다** (진흙 요괴 = 물귀신 그림, 살쾡이 요괴 = 여우불, 그슨대 · 가위 귀신 · 뱃사공 망령 = 원혼, 메기 요괴 · 야차 = 방망이 도깨비, 독두꺼비 · 화약 도깨비 · 잔나비 요괴 = 꼬마 도깨비, 화차 = 도깨비불). 불러낸 망자는 작은 해골 병사다. 시작 장면도 기존 그림을 모은 것이다. 필요한 그림은 `ASSETS.md`.
- **골바람은 요괴를 밀지 않는다** (대원만). 진흙도 대원만 느려진다.
- **한꺼번에 팔기·분해**는 일반 무기·방어구만 한다 (착용 · 잠금 · 레어 · 장신구 · 강화한 것 · 종류마다 가장 좋은 무기 하나는 남긴다). 장신구는 하나씩 정리해야 한다.
- **정예를 보스보다 나중에 잡으면** 확정 보정 경계에서 전투 화면의 빛기둥과 결과가 다를 수 있다 (서버는 정예 → 보스 순서로 판정).

- **탑 화면은 PC 크롬(450×800)에서 시작 화면 · 1~2층 · 층 카드 · 끝 카드 · '너무 빠름' 거절만 봤다** (테스트 모드, 콘솔로 출구에 옮겨서). 보스 층 카드(계속/그만)와 체크포인트에서 시작하는 흐름은 화면으로 못 보고 단위 테스트·PGlite 로만 봤다. 층마다 Phaser 게임을 새로 만들어 넘어갈 때 잠깐 끊긴다.
- **탑에서 통신이 끊기면** 그 층 보고를 한 번 더 보내 보고 안 되면 판이 끝난다(그 층 보상과 그 층에서 쓴 물약 빠짐은 없던 일이 된다). 맵처럼 보관했다가 다시 보내지 않는다.
- **탑 도중에 앱을 닫으면** 그 판은 끝나지 않은 채로 남고(다음 탑을 시작할 때 닫힌다) 그 층에서 쓴 물약은 빠지지 않는다.
- **탑과 맵 판의 시간 겹침은 서버가 보지 않는다** (탑 안에서는 층마다 서버 시계로 본다).
